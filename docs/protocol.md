# BLE 协议 v1（草案）

状态：协议 v1。2026-10-18 已有开发板连通记录；2026-10-19 的缓存推送与重连改动通过本地验证，待开发板验收。`info` 返回 `proto 1`；新增控制行是可忽略的兼容扩展，UUID、特征值和数据帧不变。

中转盒只做 SPP ↔ BLE 透传：把每个槽位的经典蓝牙串口字节流封装成 BLE 帧，不解析设备数据。槽位对应什么设备、按什么格式解析，由 InstaPunch Mapper 决定。适配新硬件只需改 App，不用改固件。

## 1. GATT 服务

广播名 `InstaPunch-Bridge-XXXX`（XXXX 为蓝牙 MAC 末 2 字节，大写十六进制；2026-10-18 起，此前为 `IPM-Bridge-XXXX`）。广播包只放标志和 128 位服务 UUID（21 字节），完整名称放在扫描响应里（24 字节）；两者合起来超过一个广播包的 31 字节。App 应按服务 UUID 扫描，名称只用于显示。

| 项 | UUID | 属性 |
|---|---|---|
| Bridge 服务 | `A7B750D5-8CE4-4F67-B586-8C1AA7800BBF` | 主服务 |
| 下行数据（设备 → App） | `D36A57C5-8A8E-4C3F-9E65-96E193551BCE` | notify，二进制帧（§3） |
| 上行数据（App → 设备） | `381B0BF7-5C19-4CCB-BF37-BC4214560D5A` | write without response，二进制帧（§4） |
| 控制 | `FC838A35-6BDB-4571-A93B-E1D2E538DECD` | write + notify，UTF-8 文本，每次一行（§5） |

为什么不需要帧头标志、转义（SLIP / COBS）或 CRC：BLE 的每个 notify / write 原样作为一个整体到达，不会被拆开或合并；链路层有 CRC，加密后还有 MIC，连接期间不丢包也不乱序。帧头只负责多路复用、标记丢失和会话、以及确认重发。

## 2. 槽位、会话与模式

- **槽位：** 共 2 个，编号 1、2，即帧里的 `channel`。每个槽位绑定一台 SPP 设备（`pair`）。
- **会话（`epoch`，0–255 循环）：** 每个槽位每次 SPP 连上时加 1，`seq` 从 0 重新开始。`epoch` 变化说明这是一段新的字节流。
- **模式**（`mode`，存于 NVS，默认 `line`）：
  - `line`：按行输出的设备（NMEA、`$PLTIT`）。只在 `\n`（`0A`）之后切包，一帧装尽可能多的完整行。只有一行比一帧长，或一行超过 200 ms 没等到 `\n` 时，才发不完整的行，并带 `PARTIAL` 标志。
  - `raw`：任意二进制。攒满一帧，或首字节到达后 15 ms，就发出。
- **离线暂存**（`hold`，存于 NVS，默认关闭）：
  - 关闭：手机没有订阅时，数据直接丢弃；手机断开时，未发出的数据也清空。
  - 开启：手机没订阅时，数据留在缓冲里，满了丢最旧的，重新订阅后补发（带 `REPLAY` 和 `AGE`）。已发出的帧保留在确认窗口里，直到 App 用 `ack` 确认（§6）。

## 3. 下行帧（notify）

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | `channel` | 槽位编号 1–2 |
| 1 | `flags` | bit0 `GAP`、bit1 `REPLAY`、bit2 `AGE`、bit3 `PARTIAL`；其余位为 0，App 遇到未知位时忽略 |
| 2 | `epoch` | 会话号 |
| 3 | `seq` | 本会话内的帧序号，0–255 循环 |
| 4–7 | `age_ms` | 仅当 `AGE` 置位时存在，uint32 小端：本帧第一个字节到达中转盒距发送时刻的毫秒数 |
| … | payload | 原始字节，至少 1 字节 |

- 帧长 ≤ MTU − 3。中转盒本地 MTU 为 517；开启 `hold` 的槽位，帧长不超过 182 字节，以便重连后按原样重发。
- `GAP`：本帧之前有数据被丢弃（缓冲溢出、手机未订阅、发送失败）。App 应丢掉解析器里拼了一半的内容，从下一行或下一个帧头重新同步。
- `REPLAY`：本帧的数据是在手机没订阅期间收到的。
- `PARTIAL`：本帧以不完整的行结束，下一帧接着这一行（仅 `line` 模式）。`line` 模式下不带 `PARTIAL` 的帧必定以 `\n` 结尾。
- 重发的帧与第一次发送时字节完全相同。App 按 `(channel, epoch, seq)` 去掉重复的帧。

App 的解析规则：每个 `(channel, epoch)` 一个缓冲区；收到带 `GAP` 的帧，或 `epoch` 变化时，清空这个缓冲区；然后按设备格式解析（行、RTCM 帧等）。

## 4. 上行帧（write without response）

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | `channel` | 槽位编号 |
| 1 | `flags` | bit0 `MORE`：同一条记录还有后续分片 |
| … | payload | 原始字节 |

- 一条记录（例如一条 RTCM 消息）可以分成多个分片，最后一片的 `MORE` = 0。中转盒收齐后整条放进该槽位的上行队列（4 KB），按 SPP 的流控事件写给设备。队列放不下时整条丢弃并计数，不会只写半条。单条记录最长 1100 字节。
- 设备未连接时，记录直接丢弃并计数。
- App 应使用 `canSendWriteWithoutResponse` / `peripheralIsReady(toSendWriteWithoutResponse:)` 控制写入节奏。

## 5. 控制命令与事件

App 向控制特征值写一行命令，回复和事件都通过同一特征值的 notify 返回，每次一行。USB 串口接受同样的命令。

| 命令 | 回复 |
|---|---|
| `info` | `bridge <固件版本> proto 1 slots 2` |
| `status` | 每个槽位一行：`<槽位> none`，或 `<槽位> <MAC> idle\|dialing\|connected <mode> hold=<0\|1> epoch=<n> lost=<下行丢弃字节>/<上行丢弃字节> [设备名]`，已绑定的槽位随后再有一行 `<槽位> rssi=<n>\|-`（见下）；最后一行：`phone <MAC> connected\|idle` 或 `phone none` |
| `devices` | 立即返回发现缓存快照，不启动搜索、不影响连接；格式见下方 |
| `scan` | 见下方“扫描与选择设备” |
| `paired` | 每台与中转盒配对过的经典蓝牙设备一行 `paired <MAC> <槽位\|-> [设备名]`，最后一行 `paired done`。`-` 表示未绑定槽位；设备名只在槽位已连接过或本次开机扫描到时才有 |
| `pair <槽位> <MAC> [PIN]` | `ok` / `error <原因>`。立即生效 |
| `forget <槽位>` | `ok` |
| `mode <槽位> line\|raw` | `ok` |
| `hold <槽位> on\|off` | `ok` |
| `ack <槽位> <epoch> <seq>` | 无回复（§6） |
| `unbind`（仅 USB） | `ok`：清除主人手机 |
| `monitor on\|off`（仅 USB） | `ok`：在串口回显设备数据 |

### 扫描与选择设备

App 发 `scan` 后，按以下顺序收到回复（2026-10-18 起；此前 `found` 行只有 MAC、RSSI 和名称）：

1. 约 10 秒的 inquiry，每发现一台设备一行：
   `found <MAC> <RSSI> <COD> <类别> <spp|-> [设备名]`
   - `COD`：6 位十六进制 Class of Device。
   - `类别`：主设备类，`misc` `computer` `phone` `lan` `av` `peripheral` `imaging` `wearable` `toy` `health` `uncategorized` `other` 之一。
   - `spp`：设备的 EIR 中列出了串口服务（0x1101）；`-` 表示不知道，**不代表不支持**（很多 SPP 设备不发 EIR，或不在 EIR 里列服务）。
   - 设备名取自 inquiry 结果或 EIR，可能为空。
2. 对没有名称的设备逐个查询名称（最多 8 台，每台 1–5 秒，超过 10 秒跳过），查到时一行 `name <MAC> <设备名>`。
3. `scan done`。

扫描期间所有槽位断开，`scan done` 后自动重连。设备名可能含空格，App 取前几个字段后剩下的整行作为名称。建议 App 把 `spp` 设备排在前面，把 `phone`、`computer`、`av` 设备排在后面，但不要隐藏任何结果；再合并 `paired` 列表中已配对过的设备（它们不一定处于可被发现状态）。用户选定后发 `pair <槽位> <MAC> [PIN]`。

### 定时推送与发现缓存（2026-10-19，固件 0.1.1）

手机完成加密并订阅控制通知后，固件在队列可用时立即补发，之后每 **5 秒**主动推送 `devices` 快照、`status` 和 `paired`。这不是定时 inquiry：**没有搜索也照常推送，不会因此断开 SPP**。队列拥塞时跳过本周期，恢复后生成最新快照，不积压旧快照。完整推送要求 ATT MTU ≥ 131；Mapper 通常协商更大 MTU，需真机核验。

```
devices begin 1
scan state idle
found 00:80:25:aa:bb:cc -70 001f00 uncategorized spp Instrument
seen 00:80:25:aa:bb:cc 45000
devices done 1
```

- `devices begin <数量>` / `devices done <数量>` 包围一份快照，数量为 0–24。中间每台设备先 `found`，后 `seen <MAC> <距最后无线发现的毫秒数>`。`scan state idle|running` 区分实际搜索状态与缓存重发。缓存重发不发送 `scan done`。
- 缓存为本次开机内存中的最近 24 台发现记录，下一次搜索不清空；满时替换最久未发现的一台，重启清空。配对及槽位配置仍按原有 NVS 保留，`paired` 独立提供已绑定设备。
- `status` 里的 `<槽位> rssi=<n>`（2026-10-21 加入，协议版本不变）：已连接 SPP 链路的实时信号，固件每 2 秒用 HCI Read RSSI 读取，10 秒内没有读数或未连接时为 `-`。`n` 是相对 ESP32 理想接收范围（−45 ～ −20 dBm）的 dB 差值：0 表示在范围内，负数表示比 −45 dBm 弱多少，正数表示比 −20 dBm 强多少。单独成行是为了让旧版 App 按“其余部分为设备名”解析槽位行时不受影响（旧版遇到两个词的槽位行会忽略）。Mac 转发器把 macOS 的绝对 dBm 换算到同一范围。
- `found` 的 RSSI 是最后发现时的值，重发不会刷新发现时间；在缓存中不等于当前可见或在线。当前槽位连接状态来自 `status` / `event link`，非槽位设备是否在线未知。
- Mapper 只用数量匹配且每条有 `seen` 的完整快照替换缓存列表；缺行保留上次完整列表，等待下一周期。旧客户端忽略新增行，仍可解析原有 `found`、`status`、`paired`；旧固件仍能被新 Mapper 使用。
- 控制通知使用 96 行有界队列，每次一个在途通知，拥塞及立即发送失败后保留重试。队列满记录警告，周期快照恢复状态；这不是应用层逐条可靠确认。单行不截断、不改变 v1 分帧；超过 MTU 的行拒发并记日志，MTU 不足时不发周期快照。5 秒仍未收到协议栈发送结果会重建手机连接，避免迟到结果确认错行。

### 重连

弱信号断开后等待 5 秒重试，两槽位轮流获得连接机会。优先使用本次开机成功查询过的 RFCOMM 通道；连接失败清除通道缓存，下次重新 SDP。30 秒只报告连接缓慢，不在 SDK 请求尚未完成时释放请求归属；待初始化失败、服务查询结果或匹配句柄的 OPEN/CLOSE 后继续。这样避免 ESP-IDF 自身 30 秒 SDP 无活动超时与应用超时竞争。若协议栈本身永不回调，仍需根据日志处理，不宣称能够自动恢复任意栈故障。重新绑定期间的旧结果不会用来拨新地址。

中转盒主动推送的事件：

- `event link <槽位> up <epoch> <设备名>` / `event link <槽位> down`
- `event lost <槽位> down|up <字节数>`：发生丢弃时推送，同一槽位每秒最多一条，数字是自上次事件以来新增的丢弃量

## 6. 确认与重发（仅 `hold` 槽位）

- 中转盒把 `hold` 槽位已发出的帧保留在确认窗口里（每槽位 2 KB）。
- App 收到帧后写入 `ack <槽位> <epoch> <seq>`，确认到这一帧为止（含这一帧）的所有帧。不必每帧都确认，建议每 0.5 秒或每 8 帧确认一次。
- 手机重新订阅时，或某帧交给协议栈失败时，中转盒先把窗口里所有未确认的帧原样重发，再发新数据。
- 窗口满时丢弃最旧的未确认帧，并计入下行丢弃。所以 App 不发 `ack` 也不会卡住，只是失去断线保护。

## 7. 安全：只认已绑定的手机

- 所有特征值和 CCC 写入都要求加密链路。App 第一次订阅时，iOS 会弹出系统配对确认框（Just Works，LE Secure Connections，带 IRK 以识别随机地址）。
- 先到先得：中转盒没有绑定手机时，第一台完成配对的手机成为主人。之后其他手机的配对请求一律拒绝，连接 30 秒内未加密会被断开。一次只连一台手机，已连接时停止广播。
- 更换手机，或手机丢失了配对信息（例如在 iOS 中“忽略此设备”）时，通过 USB 串口发送 `unbind` 清除主人。BLE 上不提供这个命令。

## 8. 其他

- 设备要求旧式 PIN 码配对时，使用 `pair` 填写的 PIN，未填时用 `0000`；使用 SSP 时自动确认。
- 槽位、模式、暂存开关保存在 NVS 中，重启后保留。PIN 码只存在中转盒上。
- 控制回复每次一行，不拆分、不截断；MTU 不足时拒发并记录日志，完整周期快照要求 MTU ≥ 131。

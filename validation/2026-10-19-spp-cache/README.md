# 2026-10-19 Bridge 0.1.1 缓存推送与弱信号重连

范围：本地源码、模拟 SDK 回调测试和编译。没有烧录、连接蓝牙设备、发布 GitHub Pages 或提交 Git。

## 行为

- 加密订阅后队列可用即补发，随后每 5 秒发送 devices 缓存快照、status、paired；不会触发搜索或断开 SPP。
- RAM 保留最近 24 台发现记录，跨搜索保留，重启清空；满时替换最久未发现记录。NVS 配对设置不变。RSSI 与 seen 毫秒年龄来自无线发现，非在线证明。
- 控制消息最多 96 行，每次一个在途通知；拥塞/API 失败保留，周期快照不积压。行超过 MTU 拒发记日志，完整推送要求 ATT MTU ≥ 131。协议栈发送完成不是应用 ACK；队列满后的状态由下一周期重新补齐。等待发送结果超过 5 秒会重建手机连接。
- SDP/连接超过 30 秒只告警，等待 SDK 的终结回调，避免旧结果被下一次拨号接收；重连缓存 RFCOMM 通道，失败后回查，两个槽位轮换。匹配 handle 才处理连接中断，改绑期间旧 SDP 不拨新 MAC。
- 手动 scan 仍会断开槽位；实际 CLOSE 后才开始 inquiry。名称补查仍可能延长扫描；迟到名称不再推进其他设备的查询。
- 新增可忽略控制行，UUID、特征值、数据帧和 proto 1 不变。新 Mapper 同时支持旧固件。

## 真机待验收

1. 单槽位稳定连接，手机前台观察至少 5 分钟，不点搜索；缓存年龄增加、槽位状态刷新，不能因周期推送而出现 SPP CLOSE。
2. 手动搜索一次，之后不再搜索；手机重连后自动收到同一缓存，发现时间不能重置为现在。
3. 逐步拉远直到真实断线，再回到近距离，分别记录断开 status/port/async、SDP/OPEN 结果及恢复时间；单槽和双槽各做多轮。
4. USB devices/status 与 App 对照；大量扫描结果与上行 RTCM 并行，检查拥塞恢复及 MTU。
5. 测试空缓存、24 条上限、重复发现、手机断连、旧 App/旧固件组合。旧客户端可忽略新行这一点由协议设计及解析源码确认，尚未做安装包交叉联调。

边界：弱信号本身仍会造成蓝牙物理链路丢失；此轮改的是可观测状态与软件恢复。SDK 若永不发终结回调仍可能停在 dialing，不用重叠请求或重置整个双模栈掩盖它。峰值内存、射频、长时间运行和手机实际协商 MTU 尚未测量。
